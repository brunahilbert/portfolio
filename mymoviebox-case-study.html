overview

MyMovieBox is a full-stack web application built on the MERN stack, offering users a database with information about movies, genres, and directors. Users can create an account, manage their personal information, and maintain a personalised list of favourite films.

The backend is a RESTful API built with Node.js and Express, connected to MongoDB. It handles CRUD operations, delivers data in JSON format, and is secured with both basic HTTP authentication and JWT authentication. The API was tested with Postman throughout development and documented on Heroku.

The React + Redux client is a single-page application with a responsive design, search and filter, detail views with related suggestions, and full favourites management. A second client was then built in Angular as a deliberate exercise to experience the same product with a different, more opinionated framework.

architecture
Backend — API
  • Node.js + Express REST API
  • MongoDB + Mongoose for data modelling
  • JWT authentication with Passport.js
  • bcrypt password hashing
  • CORS configured for multiple client origins
  • Deployed on Heroku
React Client
  • React + Redux single-page application
  • Responsive design
  • Movie list searchable by title, genre, and director
  • Single movie view with related suggestions
  • Login, registration, and profile views
  • Deployed on Netlify
Angular Client
  • Angular 16 + TypeScript
  • Angular Material UI components
  • RxJS Observables for API calls
  • Angular Router + guards for protected routes
  • Deployed on GitHub Pages
Data Model
  • Movies collection: title, description, genre, director, image
  • Users collection: username, password (hashed), email, favourites[]
  • Directors & genres as embedded documents
  • Relationships via MongoDB ObjectId references
process
01
Build the API First
Started with the backend — defining the data model in MongoDB, setting up Express routes, and wiring up JWT authentication — before writing a single line of frontend code. This gave me a clear, stable contract to build the clients against.
02
React Client
Built the React frontend incrementally: login and registration first, then the movie list, then the detail view, and finally the user profile with favourites management. Used hooks throughout and kept components focused and reusable.
03
Angular Client
Rebuilt the entire frontend in Angular and TypeScript as a deliberate learning exercise. Working in a strongly-typed, opinionated framework highlighted different trade-offs — particularly around RxJS and dependency injection vs. React's composable hooks model.
key features
🔐
JWT Authentication
Secure registration and login flow. Tokens stored in localStorage and sent on every authenticated request. Protected routes redirect unauthenticated users.
🎥
Movie Browser & Search
Browse the full movie list and filter by title, genre, or director. Each movie can be opened for a detail view that also shows related suggestions.
❤️
Favourites Toggle
Add or remove favourites from both the main list and the detail view. Keeping that toggle in sync across views — especially after a page reload — was the trickiest part of the whole project.
👤
User Profile
Profile view showing account details and favourites list. Users can update their information or delete their account entirely.

result & learnings

This was the most challenging project of the course — and the most rewarding. The client-side took much more time than expected, mostly due to troubleshooting. The hardest problem was the favourites toggle: keeping the data consistent across different views after a page reload. It took research and consulting with other developers to finally resolve, but solving it taught me more than any tutorial could.

Building the same product twice — once in React with Redux, once in Angular — was one of the most effective ways to truly understand what each framework does for you, and where the real trade-offs are.
