overview

Pokédex is a small web application built with HTML, CSS, and JavaScript that loads data about Pokémon from the open-source PokéAPI. It lets users browse the list, search for a Pokémon by name, and view each one's details.

One of the first real challenges was that the raw API data came without unit labels — so I built three custom JavaScript functions to format and display the data correctly, making it readable and meaningful for the user.

The project was part of my CareerFoundry Full-Stack Web Development training. The objective was to develop a complete, fully functional JavaScript application with a visually appealing and easy-to-use interface — a first step into building real things with JavaScript before moving into frameworks.

process
01
Research & Theme
Researched how to build a Pokémon app, paying close attention to the Pokémon visual identity — colours, logo style, and overall aesthetic — to make the interface feel true to the theme from the start.
02
Fetching & Displaying Data
Connected to the PokéAPI to load the Pokémon list and individual detail data. Because the API returns raw numbers without unit labels, I wrote three custom JavaScript functions to format and display the data properly for users.
03
Search & Detail View
Added a search engine so users can filter Pokémon by name, and built the detail view to display each Pokémon's data points in a clear, readable way — all without any page reloads.
key features
🔍
Search Engine
Users can search for any Pokémon by name. The list filters in real time without reloading the page.
📋
Detail View
Each Pokémon can be opened to view its individual data points — fetched on demand from the PokéAPI and displayed in a clear, readable format.
🔢
Formatted Data
The PokéAPI returns raw numbers without unit labels. Three custom JavaScript functions handle the formatting so the data is meaningful and readable for users.
result & learnings

I'm proud of this project. From the start I focused on capturing the Pokémon feel — researching the visual identity and making deliberate design choices — rather than just shipping something functional. Prioritising well-formatted, readable data over raw API output was an early lesson in thinking about the user, not just the code.

Looking back, one thing I'd improve is the layout on larger screens — optimising it to display multiple Pokémon per row and making better use of the available space.
